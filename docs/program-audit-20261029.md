## 复现并修正的问题

| 触发条件 | 原来的表现 | 修正后的表现 |
| --- | --- | --- |
| 饮食页开着跨过日本时间凌晨 04:00，或后台挂起后回来 | 营养页可能仍停在前一天，下一次打卡记进前一天；日期还依赖设备时区 | 当前日跟随日本时间 04:00 更新；点击打卡前也重新核对日期。手动浏览历史日期与尚未保存的热量草稿继续保留 |
| 页面已经打开，另一台设备更新相同模块 | 云端新数据写入本地后，当前文档收不到原生 storage 事件，界面仍显示旧值 | 完整同步批次安装后，再向现有模块发送对应 storage 通知；账户和饮食页面随已有刷新逻辑显示新数据 |
| 照片签名请求较慢，期间切换到另一张照片 | 旧请求晚到后可能把新照片盖回旧照片 | 每个图片节点分别校验当前请求与当前图片路径，只应用仍对应当前图片的结果 |
| 同一页面长时间运行，再次显示云端照片 | 内存缓存可能一直复用已过期的一小时签名链接 | 缓存有效期设为 55 分钟，到期重新获取签名；有效链接仍可复用 |

另外统一了各页面的云同步脚本缓存版本，补齐旧页面的角色运行时版本，并为 Claude 连接页和行李箱页预留稳定滚动条位置。
