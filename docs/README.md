# OMNITERMINAL 项目文档中心

这里是 `c-nc-pj-home` 的长期项目记忆。它用于保存用户确认的整体概念、系统结构、未决问题，以及 GPT 和 Claude 各自的施工记录。

代码可以在不同分支施工，项目记忆以 `main` 分支中的本目录为准。

## 开工前阅读顺序

1. [VISION.md](VISION.md)：用户想要的最终体验与产品原则。
2. [SYSTEM_BLUEPRINT.md](SYSTEM_BLUEPRINT.md)：当前系统分层与模块关系。
3. [DECISIONS.md](DECISIONS.md)：已确认决定、提案和待决定事项。
4. [logs/GPT.md](logs/GPT.md) 与 [logs/CLAUDE.md](logs/CLAUDE.md)：查看另一位协作者最近改过什么。
5. 再读取本次任务涉及的代码文件和目标分支差异。

## 协作规则

- 不把聊天记忆当成唯一依据；关键概念和施工结果必须写入本目录。
- `VISION.md` 记录用户目标，除非用户明确改变想法，否则不要自行改写。
- `DECISIONS.md` 中只有“已确认”可以直接作为施工依据；“提案”和“待决定”不能擅自落地。
- GPT 只追加 `logs/GPT.md`，Claude 只追加 `logs/CLAUDE.md`，不要重写或整理对方的历史记录。
- 每次代码施工后追加日志，至少写明：日期、目标、分支、提交、改动文件、验证、遗留事项、禁止误改的部分。
- 修改代码前先查看目标分支的最新文件与最近提交；不要让用户在两个模型之间反复搬运整份 HTML。
- 一个功能尽量使用一个主题明确的提交。文档更新可以单独提交。
- 不改变现有存档键、云端数据格式或用户进度，除非迁移方案已经在 `DECISIONS.md` 中确认。
- 如果实现结果与文档冲突，暂停施工并向用户确认，不以模型自己的推测覆盖用户决定。

## 当前分支约定

- `main`：稳定版本与本项目文档中心。
- `homepage-rebuild`：主页重建施工分支；合并前不影响 `main` 页面。
- 其他大型改造应使用独立分支；小型、边界清楚且已经验证的稳定修复可由用户决定是否直接进入 `main`。
